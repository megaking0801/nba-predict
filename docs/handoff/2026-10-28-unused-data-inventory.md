# 還沒用的資料：盤點與判斷（2026-10-28，評估，不是實作）

使用者的問題：「如果再把更多數據加進去分析呢？應該還有數據沒加吧？」
這份文件回答：還有哪些資料沒用、哪些在**原理上**可能含有盤口沒反映的資訊、怎麼用最便宜的方式檢驗。沒有抓取任何資料，也沒有繞過任何防護。機率都是**判斷**，不是測量。

## 0. 先講清楚「加資料」為什麼大多沒用（已量測的事實）
- 盤口在 11 個完整球季都比 fs1 ridge 準，差 **0.36 分 MAE**（`p5-market-baseline.json`）。學習曲線約 3 季就攤平（`2026-10-28-learning-curve.md`）。P4 的十一個特徵候選，最好的一個（三分出手占比）只改善 0.006 分。
- **所以「讓 fs1 更準」是錯的目標**：就算新資料讓模型改善 0.1 分，模型仍比盤口差 0.26 分，下注照樣虧。新資料只有一種有用的方式：**它含有盤口沒有反映的資訊**。正確的檢驗不是「fs1 的 MAE 有沒有下降」，而是「這份資訊能不能預測 `賽果 − 盤口` 的殘差」（P5 的框架：配對 ΔMAE 對盤口、`info_over_market` β）。
- **要多大的偏差才夠付抽水**（P5 設計 §2.4 的換算：每 1 分殘差約等於 3.2 個百分點的過盤機率）：
  - 國際盤 −110（打平要 52.4%）：某類比賽的平均殘差要 **≥ 約 0.75 分**；
  - 台彩約 1.75 兩邊（打平要 57.1%，抽水約 14%）：要 **≥ 約 2.2 分**。這在一個成熟市場裡是很大的系統性錯誤。
- **檢驗力**（殘差的標準差約 12 分，事前登記約 40 個檢驗、Bonferroni 校正後 z≈3.66）：要偵測 0.75 分的偏差，該類比賽需要約 **3,400 場**；偵測 2.2 分只要約 **400 場**。也就是說：小的子集合只能抓到「大到能付台彩抽水」的偏差，抓不到國際盤等級的小偏差。

## C. 不同「型態」的資訊（重點）
這一類不是「更多特徵」，而是問：**盤口在某些情境下是否有系統性偏差**、**盤口的移動能不能預測**。多數只用現有資料就能做，成本最低。

### C1. 盤口在子集合上的系統性偏差（事前登記的探索）
- **為什麼可能有**：市場的價格由大眾與專業資金共同決定；文獻與業界長期流傳某些偏差（大熱門／冷門、背靠背、連勝連敗後的過度反應、季末擺爛）。成熟市場多半已修正，但檢驗成本很低。
- **資料**：DB 已有收盤讓分與總分、賽果、賽程，P4.1 的情境特徵都能逐場、無洩漏地算出。
- **子集合清單（事前固定，不看結果增減）**，每項分「主隊側」與「客隊側」：
  1. 客隊背靠背；主隊背靠背；兩隊都背靠背
  2. 休息天數差 ≥ 2
  3. 客隊長途（> 2,500 km）或向東跨 ≥ 2 個時區
  4. 大熱門（|讓分| ≥ 10）；小讓分（|讓分| ≤ 3）
  5. 主隊為讓分冷門（home underdog）
  6. 季後賽；附加賽；中立場
  7. 一隊連勝 ≥ 5；一隊連敗 ≥ 5（「熱手」過度反應）
  8. 上一場輸 ≥ 20 分之後；上一場贏 ≥ 20 分之後
  9. 季初（兩隊都 ≤ 10 場）；季末最後 10 場（擺爛期）
  10. 明星缺陣後的第一場（上一場該隊上場分鐘最多的前 2 人之一沒上場；只用賽前已知的「上一場」資訊）
  11. 總分：高總分線（≥ 235）、低總分線（≤ 205）、季初總分
  12. （主線審查後加入）讓分在關鍵數字：|讓分| 等於 3 或 7；|讓分| 等於 2.5、3.5、6.5、7.5
  - **登記版本以 `jobs/market_bias.py` 的 `subsets()` 為準：24 個檢驗**（21 個讓分、3 個總分），每個檢驗以「焦點隊」的殘差做雙尾檢定（正負兩側即同一檢定的兩端），Bonferroni α = 0.01／24（z≈3.53）。
  - **國家電視轉播場：沒有測**。`games_v2` 沒有轉播欄位，scoreboard 的 `broadcasts` 從未存過；要測得重抓，不在本次範圍。
  - **和盤（push）**：殘差剛好為 0 時，平均殘差計為 0，過盤率則排除該場。2024-25 起的讓分線都是 .5，沒有和盤。
- **指標**：子集合的平均殘差（以下注側計，單位分）、ATS 過盤率（排除和盤），14 天區塊 bootstrap。
- **規則**：
  - 探索段 2015-16～2021-22；
  - 通過門檻：99% 區間（Bonferroni，約 40 個）不含 0，且平均殘差 ≥ 0.75 分（國際盤）／≥ 2.2 分（台彩）；
  - 通過的才在驗證段 2022-23～2024-25 看一次；
  - 確認段 2025-26 以後只看一次。
- **預期**：國際盤等級的偏差：可能找到 0～2 個在探索段通過、但多半驗證段不重現（先驗約 5～10% 有一個能重現）；能付台彩抽水的 2.2 分偏差：先驗 < 2%。
- **成本**：約 1 天（重用 `feature_ablation` 的 bootstrap 與 `context.py`）。

### C2. 盤口移動能不能預測（早盤 vs 收盤）
- **為什麼可能有**：收盤盤口最有效率；在早盤下注，若押的方向剛好是盤口之後移動的方向，就等於拿到比收盤好的價格（CLV）。使用者是在開賽前 8～13 小時人工下注，正是早盤。
- **問題**：「模型與開盤線的差」或某些情境，能不能預測開盤→收盤的移動方向與幅度？
- **資料**：要先重抓 ESPN odds 的開盤（`open` 區塊 2023-24 起；`Opening` 供應商 2015-16 起，要實測格式與覆蓋），只讀 GET，存資料 repo（`data/`）。
- **先驗**：能預測方向的機率約 10%（判斷）；但移動的平均幅度通常很小（多數場次不動，P5.0 的 8 場裡 87.5% 沒動，樣本極小），轉成能付抽水的優勢機率更低。
- **第一步**：重抓前先抽 50 場看 `Opening` 與 `close` 的覆蓋與差距分布；分布若集中在 0，就停。

### C3. 裁判組的總分傾向
- **為什麼可能有**：裁判組的犯規判罰習慣影響罰球數與總分；若市場只部分反映，總分殘差會在同一裁判組上持續。
- **資料**：`game_officials`（2015 起）＋收盤總分線（排除 E4 壞值）＋賽果，DB 都有。
- **注意**：裁判名單在比賽日上午才公布（約 ET 9:00，未驗證），使用者下注時間（ET 早上）差不多同時，所以服務端要確認拿得到。
- **第一步**：只讀檢驗「每位主裁判在前半段球季的總分殘差」與「後半段」的相關（split-half）；相關接近 0 就停。
- **先驗**：低（約 5%），而且這類資料業界早有人在用。

### C4. 多家莊家的分歧
- ESPN odds 在 2015～2023 有 7～16 家莊家。分歧大的場次，是否代表盤口較不確定、收盤後的殘差較大或有方向？
- 對使用者沒有直接用處：他只能在台彩下注，不能比價。先驗低。**列入不做**，除非 C2 重抓時順便有資料。

## 前 3 名（建議順序）
1. **C1 子集合偏差探索**：只用 DB 現有資料，約 1 天，規則事前登記。即使結論是「沒有」，也直接回答了使用者「是不是還有沒用到的資訊」。
2. **C2 盤口移動可預測性**：先抽 50 場確認開盤資料可用（只讀 GET），再決定要不要重抓全部。這是唯一和「使用者在早盤下注」直接相關的方向。
3. **C3 裁判組總分傾向**：資料都在 DB，split-half 檢驗很便宜；通過才往下。
（另：Jbot 台彩比對已備好，等使用者金鑰；它不需要新開發。）

## 不值得做
| 項目 | 理由 |
| :- | :- |
| 再加 fs1 特徵（出手桶、球員進階、教練輪替） | 目標錯誤：fs1 離盤口差 0.36 分，P4 最好的特徵只改善 0.006 分 |
| 逐回合／on-off／RAPM | 要重抓大量資料、條款灰區、陣容資訊盤口早已反映 |
| 球員追蹤、對位 | 沒有免費且條款可用的來源 |
| 賽季前勝場數盤、交易與合約 | 本身是市場資訊或盤口早已反映；取得來源條款不明 |
| 社群情緒、全網新聞、大眾投注比例 | 已評估或來源付費、條款不明；先驗很低 |
| 天氣、場館 | 不適用（海拔已測：−0.001） |
| 多家莊家分歧（C4） | 使用者只能在台彩下注，用不到比價 |

## 給使用者的一句話
還有資料沒用，但「加資料讓模型更準」這條路已經量過：資料量與特徵都不是缺口，盤口本身就比模型準。剩下值得一試的，是用現有資料檢查「盤口在某些情況下是否有固定的錯誤」，以及「盤口的移動能不能預先猜到」；這兩件成本低、規則先寫死，但成功的機率我判斷都不高，要能付台彩約 14% 的抽水更低。
