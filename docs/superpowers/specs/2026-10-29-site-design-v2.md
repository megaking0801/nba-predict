# 網站設計 v2：從中線出發的勝率（2026-10-29）

狀態：提案，待主線互審；通過後在 `site-simplify` 上實作（先 CSS、再版面），不 push。
起點：v1 簡化（`2026-10-29-site-simplify-design.md`，已實作在 `site-simplify`）乾淨但沒有個性。v2 只加**一個**有主題的記憶點，其餘維持安靜。

## 1. 概念與唯一的記憶點
**對象與任務**：給朋友看的「今晚 NBA 每場誰比較會贏」。打開要立刻看懂：哪場一面倒、哪場是五五波。

**記憶點：從中線出發的勝率條（中場線勝率條）**
- 一條細長的「半場」軌道，正中間畫一個小小的中圈記號（球場中線）。填色**從中線往被看好的那一隊延伸**，長度是「離五五波多遠」：勝率 50% 時沒有填色，80% 時填滿那一半的 60%（(0.80−0.5)×2）。
- 填色用**被看好那一隊的代表色**，是整個網站唯一的彩度，也是球迷一眼認得的東西。客隊在左、主隊在右，和比賽列的隊名位置一致。
- 為什麼這比 v1 的「兩段分割條」好：
  - 分割條每一場看起來都差不多滿，看不出一面倒還是五五波；中線條在五五波的場次**幾乎是空的**，這正好誠實地表達「這場模型也不知道」。
  - 它沿用球場的語彙（中線、中圈），不是抽象的進度條。
- 可實作、不炫：純 CSS（`left:50%` 或 `right:50%`、`width` 由勝率算出），沒有動畫。中圈用 `::after` 畫，不用圖片。

```
勇士 客   34%  ├──────────────○▓▓▓▓▓▓▓───────────────┤  66%  主 湖人
                              ↑ 中線：50%      填色＝湖人代表色，長度＝(0.66−0.5)×2 的一半
公牛 客   49%  ├──────────────○▏─────────────────────┤  51%  主 塞爾提克   ← 五五波：幾乎沒有填色
```

## 2. 色票

> **主線審查決定（2026-10-29）：不用 30 隊代表色，填色用墨色（深色模式 `#C9D2DE`）。** 理由：一頁十幾場會再變花、隊色憑記憶未查證、被看好隊的隊色會讀成推薦色、省掉一組對比測試。下面關於隊色的段落保留作為紀錄，**沒有實作**。

UI 只有「紙、面、墨、次要墨、線」五個中性色；彩度只出現在勝率條（各隊代表色）與結果字（命中／未中）。

| 名稱 | 淺色 | 深色 | 用途 |
| :- | :- | :- | :- |
| 紙（底） | `#F2F4F6` | `#0F131A` | 頁面底色，冷灰，不是奶油色 |
| 面 | `#FFFFFF` | `#171C24` | 比賽列表、詳細頁面板 |
| 墨 | `#142033` | `#E6EAF0` | 主要文字；帶藍的深墨，不是 `#111` |
| 次要墨 | `#566173` | `#9AA4B2` | 時間、標籤、說明 |
| 線 | `#DCE1E7` | `#29313C` | 分隔線、勝率軌道 |
| 命中／未中 | `#1F7A4F`／`#B4372E` | `#5CC48F`／`#F07A6E` | 只用在已結束場次的結果字，永遠搭配文字 |

- **連結**用墨色加底線，不另設強調色；焦點框用墨色 2px。
- **各隊代表色**（30 個 hex，取各隊較深的主色以確保對比）只用在勝率條。深色模式用 `color-mix(in srgb, 隊色 62%, white)` 提亮。測試會逐隊檢查：淺色模式對白色面、深色模式對深色面的對比 ≥ 3:1（WCAG 圖形元素門檻）。**這 30 個值是我依記憶輸入的公開配色，未逐隊查證**；實作時列出來請主線核對，有疑慮的隊用中性墨色代替。
- **為什麼不落入套路**：
  - 不是奶油底＋襯線＋赤陶色（底是冷灰，沒有襯線，沒有暖色強調）；
  - 不是近黑底＋酸綠（淺色為主，深色也是帶藍的深灰，沒有螢光色）；
  - 不是 SaaS 卡片組（只有一個列表面板，沒有陰影、沒有漸層）。
  - ui-ux-pro-max 的「Sports Team」配色（紅 `#DC2626`、粉紅底）不採用：紅色在這裡會被讀成「警告／虧損」，和誠實立場的語氣衝突。它的「Analytics Dashboard」（藍＋琥珀）也不採用：那就是 v1 的樣子，沒有個性。

## 3. 字體
- **維持系統中文字**：`"PingFang TC", "Noto Sans TC", "Microsoft JhengHei", system-ui, sans-serif`。
- 數字一律 `font-variant-numeric: tabular-nums`。勝率數字用 600 字重、比內文大一級，是唯一放大的文字。
- **不用 Google Fonts**：
  - 中文網頁字型（例如 Noto Sans TC）就算只取一個字重也有數 MB 的分片，要多好幾個外部請求，手機上首次載入明顯變慢；
  - 只為數字加一套拉丁字型可行（幾十 KB），但會多一次外部請求，網路不穩時數字還會換字（FOUT）。
  - 記憶點已經放在勝率條，字型不需要再搶戲。ui-ux-pro-max 的 ux 查詢也提醒「避免阻擋首次繪製的資源」。
- 字級：13（輔助）／15（內文、隊名）／18（勝率）／24（頁首標題），行高 1.6。

## 5. ui-ux-pro-max 查詢與取捨
| 查詢 | 回傳重點 | 採用？ |
| :- | :- | :- |
| `--domain ux "data-dense sports scores list mobile first accessibility"` | (1) 手機優先，先寫手機樣式再加斷點；(2) 批次操作；(3) 關鍵 CSS 內嵌，避免阻擋首次繪製的資源 | (1) 採用：CSS 改成手機預設、`min-width` 斷點。(2) 不適用：本站沒有編輯操作。(3) 採用：CSS 已內嵌，並以此為由不加網頁字型 |
| `--domain color "sports statistics analytics neutral light"` | Analytics Dashboard（藍 `#1E40AF`＋琥珀）、Sports Team（紅 `#DC2626`＋金，粉紅底）、Documentation（灰階） | 都不採用作為主色。紅色會讀成警告／虧損；藍＋琥珀就是 v1 的平淡。採用它的 Documentation 型中性灰階**結構**（底／面／墨／線），彩度改由各隊代表色承擔 |
| `--domain chart "probability comparison two values diverging bar"` | 雷達圖（不適用）、散布圖（不適用）、長條圖：直接標數值、不可只靠顏色、要有文字替代 | 採用無障礙原則：兩個勝率永遠以數字直接標在條的兩端；顏色只是加強；條本身 `aria-hidden`，數字是文字。不採用「每條不同色」的通用建議以外的部分 |

查詢結果與誠實立場衝突時以立場為準：沒有任何「推薦」視覺（例如高亮「最佳選擇」、皇冠、火焰圖示）。

## 6. 自我審查（對照清單）
| 清單項目 | 狀態 |
| :- | :- |
| 對比 ≥ 4.5（文字） | 墨 `#142033` 對 `#FFFFFF` 約 16:1；次要墨 `#566173` 對白約 6:1；深色同樣檢查，實作時加測試計算 |
| 圖形元素 ≥ 3:1 | 各隊代表色逐隊測試（§2） |
| 可見焦點 | 整列連結 `:focus-visible` 2px 墨色框 |
| `prefers-reduced-motion` | 沒有動畫，不需要；保留規則以防日後加入 |
| 不用表情符號當圖示 | 只剩警語的「⚠」（是文字符號，前面有文字說明）；中圈記號用 CSS |
| 可點 ≥ 44px | 比賽列最小高度 56px |
| 375／768／1024／1440 | 手機兩行列、其餘單欄列，最寬 880px |
| 字級 ≥ 14 | 只有時間與註記用 13px；改成 14px，內文 15px |

**修掉的預設套路**：
- v1 的「單一藍色強調色＋分割條」：這是任何儀表板都會出現的樣子，改成中線條與隊色。
- 刪掉「時間外猜中率」大數字三格卡片的放大字，改成同一字級的三欄文字。原本的做法就是「大數字＋小標籤」的預設。
- 不加 hero 圖片、不加漸層標題、不加全大寫英文小標、不用「 · 」串接、連結不加「→」。
- 比賽列不做成獨立卡片牆，而是一個面板裡的列。

## 7. 不變的項目
非投注警語與「高命中率不等於能獲利」「不是穩賺明牌」；P6.1 讓分卡規則（不顯示過盤機率、不寫看好破盤、不貼命中徽章，逐字不動）；大小分 48% 警語；台北時間；`esc()`；過期與「還沒出來」的 JS 邏輯；`render.py` 不 import streamlit；Streamlit 外殼維持淺色可讀。
