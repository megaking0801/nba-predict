## 2. 會誤導或過時的文案（一併處理，屬刻意的行為變更）
- 「三季、4000+ 場」出現在 hero、模型說明、免責聲明：資料已是 12 季、約 1.4 萬場。改成由資料帶出的數字，不再寫死。
- 「近三季猜中率」：實際是 walk-forward 全期（13,017 場）。改成「時間外驗證猜中率」並附場數。
- 「今晚最有把握的一場」＋「信心 高／中／低」（`_conf_word` 只看離 50% 多遠）：「把握」與「信心」暗示可以下注。改為「勝率差距最大的一場」或拿掉焦點卡（建議拿掉，見 §3），並移除「信心」字樣（P6 設計 §3.2 已要求）。
- 「看好 X（主）贏」：改成「勝率較高：X」，去掉推薦語氣（P6 設計 §3.2）。
- 免責聲明的「模型擅長預測勝負」：盤口在 11 季都比模型準 0.36 分。改成「模型會猜勝負，但不比盤口準」。

## 3. 簡化方向
**定位**：給朋友看的「今晚賽程＋模型勝率」，像一張乾淨的賽程表，不像遊戲大廳。

**顏色（淺色為主，跟系統切換深色）**
| 角色 | 淺色 | 深色 |
| :- | :- | :- |
| 底 | `#F5F6F8` | `#14161A` |
| 面 | `#FFFFFF` | `#1C1F25` |
| 文字 | `#17191E` | `#E8EAEE` |
| 次要文字 | `#5D6470` | `#9AA1AC` |
| 線 | `#DCDFE5` | `#2B3038` |
| 唯一強調色（球場藍） | `#2453C8` | `#7FA2FF` |

- 結果用語義色，只出現在「已結束」的場次：贏 `#1F7A4F`、輸 `#B4372E`，且一律加文字，不只靠顏色。
- 警告（過期、警語）：用一般文字色加左邊線，不用琥珀色底。

**字體**：只用一套系統中文字（`"PingFang TC", "Noto Sans TC", "Microsoft JhengHei", system-ui, sans-serif`），數字用 `font-variant-numeric: tabular-nums` 對齊。拿掉 Google Fonts（少兩個外部請求，中文不再混字）。字級：14／16／20／28 px 四階。

**版面（手機優先）**
```
今晚 12 場（台北時間）              資料更新 10/28 22:56
───────────────────────────────────────────────
19:00  公牛  @  塞爾提克        20%  ████████░░  80%
19:30  勇士  @  湖人            44%  █████░░░░░  56%
...
───────────────────────────────────────────────
已結束（10/27）   湖人 108 : 103 勇士   勝率較高的一方 贏
```
- 首頁：今天一組場次＋前一天的結果，其他日期收在「更早的預測」連結，不再同時列 5 天。
- 每場一列，不是卡片。一列只有：時間、兩隊、兩個勝率數字、一條細的勝率條（6px）。點整列進詳細頁。
- 寬螢幕最多兩欄，內容最寬 960px，文字靠左。
- 詳細頁：勝負、讓分、大小分三塊照現在的內容，改成同一個面加分隔線，不再是三張發光卡。
- 戰績、模型說明、免責放在頁尾，同一種樣式，字小一級。

**唯一的視覺重點**：勝率數字。用較大的等寬數字並排兩隊勝率，這是整頁唯一放大的元素；其餘全部安靜。

**動態**：全部拿掉（脈動、hover 上浮、發光）。只保留鍵盤焦點框與點擊回饋。

**文字細節**：小標用一般大小寫中文，不用全大寫英文小標；不用「 · 」串接；連結不加「→」；表情符號只保留 ⚠（警語），結果用「贏／輸」文字。

**無障礙**：文字對比 ≥ 4.5:1；手機最小字 14px；可點區域 ≥ 44px 高；看得到的焦點框。

## 4. 一定要保留的（誠實立場，CLAUDE.md）
- 「僅供球迷參考與娛樂，非投注建議」；「高命中率不等於能獲利，運彩賠率早已反映強弱」；「不是穩賺明牌」。
- **P6.1 讓分卡規則**：只顯示盤口、模型分差與「比盤口多給主／客隊幾分」、固定警語；**不顯示過盤機率、不寫「看好破盤」、不貼命中／未中徽章**（`tests/test_webui_render.py` 已鎖）。
- 大小分卡：以「模型估總分」為主，方向只是弱傾向，附 48% 的警語。
- 戰績區的 walk-forward 說明與場數；資料來源（ESPN）。
- 過期警告（超過 36 小時）與「今天的預測還沒出來」提示（`static_page` 的兩段 JS 邏輯不動）。
- 所有時間標「台北時間」；DB 來的文字一律經 `esc()`。

## 5. 不能破壞的東西與驗證
- `NEON_CSS` 與每一段 HTML 都進 Streamlit 整頁 golden（`tests/test_streamlit_golden.py`）。**這次改版會讓 golden 全面改變，是刻意的行為變更**：每個實作步驟各自一個 commit，commit 訊息列出變更清單；更新 golden 前先用文字 diff 確認只改了預期的部分（例如步驟 1 只該動 CSS 那一段）。
- `render.py` 規則不變：不 import streamlit、`esc()`、純函式。
- Streamlit 外殼（`.stApp`、側欄、選單、按鈕）要保留可用的樣式，因為兩邊共用同一份 CSS。
- 截圖驗證：需要一個不用 DB 的預覽方式。建議加一個小腳本，用 `tests/fakes.py` 的假資料把首頁與詳細頁渲染到暫存目錄，再用瀏覽器（Claude in Chrome）看淺色、深色、手機寬度三種。

## 6. 實作步驟（建議）
1. **只換 CSS**：新的色票、字體、拿掉發光／漸層／動畫；HTML 不動。golden 只有 CSS 段改變。
2. **版面**：場次卡改成列、拿掉焦點卡、首頁只放今天＋昨天結果、詳細頁三塊合併。golden 改 HTML 結構。
3. **文案**：§2 的五項。golden 改文字。
4. 截圖驗證、主線互審、使用者看預覽後再部署（push 要使用者同意）。
每一步都跑 `python -m pytest tests -q`，並貼 golden 的差異摘要。

## 7. 要使用者決定的
- 淺色為主（跟系統切深色）還是深色為主。我建議淺色為主：資訊型網站在白天與手機上比較好讀。
- 首頁只放今天＋昨天的結果，其他日期收起來，可以嗎？
- 要不要拿掉「今晚最有把握的一場」焦點卡（我建議拿掉）。
