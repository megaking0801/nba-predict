# 串關／抽水計算器：小設計（2026-10-28，未實作，等使用者選方向）

上層：`docs/superpowers/specs/2026-10-26-p6-honest-site-design.md` §3.6。
定位：**只算機率與期望值，不推薦、不預測**。使用者自己輸入台彩賠率與自己估計的勝率；不用任何第三方資料，所以沒有 ESPN 授權問題。

## 1. 使用情境
使用者最常玩受讓分串 2～3 關（總體規劃 §1）。計算器回答三個問題：
1. 這張串關要「每一關」贏多少機率才不虧？（損益兩平）
2. 照我估計的勝率，這張單的期望值是多少？
3. 台彩這個賠率裡抽了多少水？

## 2. 輸入（全部由使用者填，純前端，不送出任何資料）
- 關數 n：1～6（台彩實際允許的關數**未查證**，介面寫「以台彩規則為準」）。
- 每關：十進位賠率 `o_i`（必填，1.01～50）；我的估計勝率 `p_i`（選填，0～100%；沒填就用損益兩平值，只顯示門檻）。
- 選填：同一場的另一邊賠率 `o_i'`（用來算這一關的抽水）。
- 注金（選填，預設 100 元，總體規劃 §7 的「以每張 100 元為基準」）。

## 3. 輸出與公式
- 串關賠率 `O = ∏ o_i`；過關機率 `P = ∏ p_i`（**假設各關獨立**；同一場不同玩法、同隊相關的關不獨立，介面明講）。
- 期望值（每 1 元）`EV = P × O − 1`；以注金換算成元；顯示「長期每投 100 元，平均回收 X 元」。
- 每關損益兩平 `p*_i = 1 / o_i`；整張損益兩平（各關同賠率 o）`P* = (1/o)^n`。例：每關 1.75 → 每關 57.1%，三關整張 18.7%。
- 單關抽水（有兩邊賠率時）`v = 1/o + 1/o' − 1`；去水後的隱含機率 `(1/o)/(1/o + 1/o')`。例：1.76／1.74 → 抽水約 14.3%（主線用 Jbot 文件樣例算出）。
- 串關的抽水會疊加：若每關都公平定價（去水機率），`EV = ∏(p_i × o_i) − 1`，n 關抽水 v 時約為 `(1 − v/(1+v))^n − 1`（例：v=14.3%、3 關 → 約 −33%）。介面用一句話說明「關數越多，抽水越重」。
- 固定一句話：「沒有優勢時，串關的期望值一定是負的；高勝率不等於賺錢。」

## 4. 不做的事
- 不給「建議串哪幾關」、不給任何場次的勝率預設值（避免變成推薦）。
- 不顯示「最低可接受賠率」作為行動建議（前提不成立，P6 §1）。
- 不存使用者輸入（不用 localStorage，除了可選的「記住上次的關數」）。

## 5. 技術與測試
- 靜態站（`webui/`）的一個獨立頁，內嵌 JS，無外部依賴；`render.py` 規則不變（不 import streamlit、DB 文字經 `esc()`；此頁沒有 DB 文字）。
- 公式在 Python 有一份對照實作（`webui/parlay.py`），單元測試用同一組輸入比對 JS 與 Python（JS 用 node 跑的話要確認 CI 有 node；沒有就只測 Python，JS 用瀏覽器實測）。
- 邊界：賠率 1.01 與 50、機率 0 與 100%、空白、非數字、n=1。
- 瀏覽器實測（Claude in Chrome）：載入、輸入、改關數、手機寬度。

## 6. 未驗證
- 台彩串關規則（最少／最多關數、同場是否可串、和局或延賽怎麼算、是否另有串關抽成）。
- 台彩實際賠率的抽水是否都約 14%（只算過一個樣例）。

## 7. 需要使用者決定
- 要不要做（屬 P6 方向，使用者還沒選）。
- 放在現有網站，或獨立頁（作品集用）。
