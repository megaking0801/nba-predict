# 網站重新設計 v4（2026-10-29，主線起草，待支線審）

使用者回饋：v3「更難看」，要求用 frontend-design 從零重做；先學類似網站與簡約美學；目標「清楚但好看」。
範圍：視覺與版面。不改資料、模型、預測邏輯。保留項見 §6。

## 1. 先學到的（來源與限度）
我讀了 Apple Sports 的設計評論（[Lickability](https://lickability.com/blog/apple-sports/)、[Creative Boom](https://www.creativeboom.com/inspiration/this-new-app-from-apple-has-something-important-to-teach-us-about-designing-data/)，皆已讀頁面）與一般簡約網頁設計原則的搜尋摘要（未逐篇核對）。評論是作者的解讀，不是 Apple 文件。
可用的結論：
- **記分板的共通語彙是「一隊一行」**：兩隊各佔一行，右側是大而粗的數字。讀者不必學任何圖形語言。
- **數字用粗而窄的字體**是主角（Apple Sports 的比分用粗體窄寬）；其他文字安靜。
- **克制**：沒有橫幅、影片、聊天機器人；留白把密集資料分組；顏色有目的而不是裝飾；用圖示或符號減少閱讀量。
- **日期切換**（昨天／今天／之後）讓人先找到「我在哪一天」。
- 反面：有評論指出好看的圖表若取代了精確資料就是倒退。所以我們保留精確數字，不用圖表取代它。
- 一般簡約原則（搜尋摘要）：階層靠字級與留白，不靠陰影漸層；一個強調色加中性色；字太細是最常見的可讀性失敗。

## 2. 為什麼 v1～v3 不對（我的診斷，未經使用者驗證）
- v1 霓虹：太花。v2：太平，沒有識別。
- v3「中線」：概念只對我們有意義，讀者看不懂一條貫穿的線；隊名離數字與條很遠，視線要來回跳；巨大日期「23」與內容無關卻最醒目；整頁只有灰藍墨色，仍沒有溫度。
- 共同問題：**沒有球隊識別**。球迷是靠隊色與隊名認場次的。

## 3. 概念：「一張乾淨的今晚記分表」
一個窄欄（最寬 560px，桌機置中，手機滿版），一張白色的「紙」放在淡灰底上。每場兩行（一隊一行），隊名左、勝率右。**唯一的色彩是 30 隊的隊色小方塊**（隊名縮寫，28px 圓角方塊），其餘全是墨色與灰。記憶點：粗窄的勝率數字，被看好的隊用墨色粗體、另一隊用灰色，所以一眼看得出誰較高，不需要條或線。
隊色來源：ESPN `/teams` API 的 `color` 欄位（我已對正式 API 抓取並逐隊列出，見 §7），不是憑記憶。方塊上的字依亮度選白或墨色；方塊只是身分標記，不填滿任何勝率。

### 版面線稿（手機與桌機同一欄）

```
┌────────────────────────────────────────────┐
│ 今天  10 月 29 日 週四（台北時間）     12 場 │
├────────────────────────────────────────────┤
│ 07:30                           尚未開賽    │
│ [GS ] 勇士                           34     │
│ [LAL] 湖人                           66     │
├────────────────────────────────────────────┤
│ 10:00                  終場 105 : 110  命中 │
│ [NY ] 尼克                           26     │
│ [BOS] 塞爾提克                       74     │
├────────────────────────────────────────────┤
│ … 其餘場次，每場一個區塊，細線分隔          │
└────────────────────────────────────────────┘
        ▸ 昨天的結果（10 場）    ▸ 其他日期

模型戰績（一張紙：三個數字橫排，沒有邊框）
說明與免責（小字，同一張紙）
```
- 勝率數字：粗窄字體 28px，右對齊、tabular；被看好的一隊墨色，另一隊灰色（`#667085`）。數字後面加小的「%」（14px，灰）。
- 一行高度 ≥ 48px，整個場次區塊可點，進詳細頁。
- 每場區塊之間只有 1px 細線，不是每場一張卡片（避開「一堆相同圓角陰影卡」的套路）。
- 首頁「今天」展開；「昨天的結果」與「其他日期」用 `<details>`，預設收合（昨天預設展開一場摘要也可，見 §8 我的決定）。
- 詳細頁：同一欄；頂部是同樣的兩行記分（較大）；下方「勝負／讓分／大小分」三段用細線分隔、同一張紙；傷兵名單兩欄在寬螢幕、單欄在手機。

## 4. 視覺 token
| 角色 | 淺色 | 深色 |
| :- | :- | :- |
| 底（頁面） | `#F2F4F7` | `#0B0D12` |
| 紙（內容） | `#FFFFFF` | `#151922` |
| 墨 | `#101828` | `#F2F4F7` |
| 次要墨 | `#667085` | `#98A2B3` |
| 細線 | `#E4E7EC` | `#232A36` |
| 命中（只用在結果文字） | `#1F7A4F` | `#4CC38A` |
| 未中（只用在結果文字） | `#B4372E` | `#F08A82` |
- 對比我會在實作時用計算驗證：墨對紙、次要墨對紙與對底、命中與未中對紙，全部要 ≥ 4.5:1（未驗證，數值是起點）。
- 隊色方塊：30 個 ESPN 色，方塊內縮寫字依相對亮度選白或墨色（≥ 4.5:1）；深色模式方塊不變（色塊本來就是飽和色）。
- 圓角只有兩種：紙 16px、隊色方塊 8px。沒有陰影、沒有漸層、沒有發光。
- 間距尺度 4／8／12／16／24／40。

## 5. 字體與動態
- 中文與內文：系統中文字（`"PingFang TC","Noto Sans TC","Microsoft JhengHei",system-ui,sans-serif`），內文 16px、行高 1.6；次要 14px。
- 數字：沿用 v3 已經在庫的 Barlow Semi Condensed 子集（只含數字與「%:」，約 6 KB），失敗時退回系統數字；勝率用 600 粗度。**不再新增字型**。
- 字級：14／16／20／28。大標只有「勝率數字」一處是 28。
- 動態：只有按下回饋（背景色 120ms）；尊重 prefers-reduced-motion。沒有載入動畫。

## 6. 不變項
非投注警語（「僅供球迷參考與娛樂，非投注建議」「高命中率不等於能獲利」「不是穩賺明牌」）、P6.1 讓分卡規則與文字逐字不變、大小分 48% 警語、時間標台北、DB 文字經 `esc()`、過期警告與「還沒出來」的 JS 邏輯、v3 已修的過時文案（資料年份、猜中率名稱、「勝率較高：X」）、手機 375px 可用、對比 ≥ 4.5:1、可點區域 ≥ 44px、`aria-label`（每個場次區塊要有完整文字，如「勇士（客）34%，湖人（主）66%，10/29 07:30 台北時間，尚未開賽」）。
刻意行為變更：整頁 golden 會全面改變；分兩個 commit：先 CSS（HTML 不動，golden 只動 `<style>`）、再版面；每步先做文字 diff 確認只改預期部分。v3 的中線、大日期數字、`.nb-mid` 等元素移除。

## 8. 我的決定（可被推翻）與風險
- 昨天結果預設收合，不展開（首頁先看「今晚」）。
- 不放勝率條：被看好者用粗體墨色表示；若測試讀者覺得不夠直覺，再加一條 3px 的細條放在兩行下方（備案）。
- 30 色方塊會讓首頁一次出現很多顏色，但每個只有 28px；若實際預覽覺得花，備案是只保留縮寫文字、方塊改墨色外框。
- 未驗證：隊色對比（GS 黃色方塊配墨色字）、真實資料下的長隊名（塞爾提克）在 375px 的排版、深色模式的觀感。

## 9. 自審（frontend-design 的預設套路清單）
- 奶油底＋襯線＋赤陶：沒有（冷灰底、系統無襯線）。
- 近黑底＋酸綠：深色是藍灰，不用亮色強調。
- 報紙式細線、零圓角：沒有；有圓角紙。
- 一堆相同卡片：沒有；一張紙內用細線分隔。
- 全大寫標籤、「 · 」串接、「→」、單字上色標題：沒有（日期列不使用「 · 」）。
- 大數字加小標籤的三格卡：戰績改成橫排文字欄，不放大。
- 唯一的視覺重點：勝率數字；其餘安靜。
