# 網站設計 v3：有設計感但克制（2026-10-29）

狀態：提案，給主線挑方向；挑定後在 `site-simplify`（已部署的 v2）上實作，預覽通過後再問使用者部署。
使用者對 v2 的回饋：「現在很清楚，但沒有任何的設計」。
不變（三個方向都遵守）：
- 非投注警語、P6.1 讓分卡規則、大小分 48% 警語；
- 台北時間、`esc()`、過期與「還沒出來」的 JS 邏輯；
- 文字對比 ≥ 4.5、375px 可用；
- 不用霓虹、發光、漸層；不用「把握」「推薦」語氣。

## 0. 先回答「為什麼 v2 沒有設計感」
- 只有一個記憶點（中線條），而且縮在每一列裡，**沒有一個頁面層級的形狀**：頁首、主視覺、列表、頁尾全是同一個灰白節奏。
- 沒有識別：網站名稱只是一行粗體字。
- 數字和文字同一套系統字，數字沒有性格；可是這個網站的主角就是數字（勝率、時間、比分）。

三個方向各自用**不同的槓桿**補上這三點，不是同一個方向的微調。

## 方向 A：一條貫穿全頁的中線（建議）
**一句話**：把 v2 每列裡的中線拉成一條從頁首貫穿到頁尾的 50% 線，整頁就是一張「今晚每場離五五波多遠」的圖。

```
╭─────────────────────────────────────────────────────────╮
│ NBA 勝負預測                        時間外猜中率 66%     │
│                                                         │
│ 30                     今晚 12 場                        │
│ 10 月  週五           每場只用開賽前的資料。勝率不是推薦。  │
│ ─────────────────────────────┼───────────────────────────│ ← 中線（50%）從這裡開始往下
│ 07:00  勇士      34%         │●━━━━━━━━         66%  湖人  │
│ 07:30  公牛      49%        ●│                  51%  塞爾提克│
│ 08:00  太陽      58%  ━━━━━━●│                  42%  金塊  │
│        …                     │                             │
│ ─────────────────────────────┼───────────────────────────│
│ 10/29 已結束                 │                             │
│ 終場   尼克 105  26%          │●━━━━━━━━━━━     74% 110 塞爾提克 命中│
╰─────────────────────────────────────────────────────────╯
```
- **主視覺**：左上一個大日期數字（「30」約 64px，下面小字「10 月 週五」），右邊「今晚 12 場」。這是唯一的大字。
- **列表**：所有場次共用同一條垂直中線，它畫成頁面上真的一條 1px 墨線，穿過每一列和日期分隔。每場的填色從中線往被看好的一方延伸，端點一個小圓點。
  - 版面節奏自然出現：接近五五波的場次填色很短、擠在中線旁；一面倒的場次填色很長。
  - 排序仍是開賽時間，不另外加權或標記。
- **手機 375px**：中線放在第二行的條中央。每場兩行，同 v2 修正版，但條與中線在每一列對齊，整頁仍看得到一條連續的中線（列與列之間的中線用 1px 線段補上）。
- **色票**（淺／深）：紙 `#F4F5F2`／`#11151B`、面 `#FFFFFF`／`#181D25`、墨 `#152033`／`#E7EBF0`、次要墨 `#59636F`／`#9BA5B2`、中線 `#152033`／`#C9D2DE`。命中、未中文字色沿用 v2。
- **字體**：中文系統字。**數字用 Barlow Semi Condensed 600，只載入數字與「%:」**（Google Fonts 的 `text=` 參數只回傳需要的字形，估計約 3～6 KB 的 woff2，一個 CSS 請求加一個字型檔，`display=swap`；未實測）。字型載入失敗時退回系統 tabular 數字，版面不跳動。
- **動態**：頁面載入時，中線由上往下畫一次（0.5 秒），各列填色在中線畫到時才出現。只此一次，`prefers-reduced-motion` 時直接顯示。
- **風險**：
  - 中線要跨列對齊，CSS 要用固定的三欄格線（隊名、條、隊名），在 375px 要仔細測。
  - 「大日期數字＋小標籤」接近 frontend-design 說的預設手法。這裡有理由：日期就是這一頁的主題，而且只用一次。
- **成本**：中。CSS 為主；`prob_bar` 增加端點圓點；頁面多一個垂直線元素。

## 方向 B：戰術板（X 與 O）
**一句話**：用教練戰術板的符號系統——客隊是 ✕、主隊是 ○——讓每一列像一張小戰術圖；識別來自符號，不來自顏色。

```
NBA 勝負預測  ✕ ○                                 時間外猜中率 66%
┌───────────────────────────────────────────────────────────┐
│  今晚                                         ╭───╮         │
│  12 場          ─────────────○─────────────   │ ○ │ 半場圖  │
│  10/30 週五                                   ╰───╯         │
└───────────────────────────────────────────────────────────┘
07:00   ✕ 勇士   34%  ├──────○▓▓▓▓────┤  66%  湖人 ○
07:30   ✕ 公牛   49%  ├──────○▏───────┤  51%  塞爾提克 ○
```
- **識別**：
  - 網站名稱旁一個 ✕ 一個 ○ 的小標誌（CSS 畫，不是表情符號）；
  - 主視覺是一個用線條畫的半場（中線、中圈、三分弧，SVG 內嵌）。半場圖本身沒有數據，只當識別。
- **兩個「隊伍側」顏色**：客隊符號用板擦藍 `#2C55A8`，主隊符號用板擦紅 `#B93A32`，只用在 ✕／○ 符號與勝率條兩端的小記號，不用在填色。
  - 這是位置（客／主），不是被看好的一方，所以不會讀成推薦色。
  - 代價：紅色仍可能被讀成「警告」。
- **色票**：白板 `#FBFCFD`／`#12161C`、面 `#FFFFFF`／`#1A1F27`、墨 `#1A2230`／`#E6EAF0`、次要墨 `#5B6472`／`#9BA5B2`、客藍 `#2C55A8`／`#8EA8E6`、主紅 `#B93A32`／`#EE8A80`。
- **字體**：中文系統字；數字用 **Barlow Condensed 600**（只載數字，同 A 的作法）。戰術板手寫字型不採用，中文沒有對應字形，混用會很怪。
- **動態**：半場圖的線條載入時畫一次（stroke-dashoffset），`prefers-reduced-motion` 時直接顯示。
- **風險**：
  - 符號系統要教育使用者（頁首一行說明「✕ 客隊　○ 主隊」）；
  - 兩個彩色比 A 多；
  - 半場圖是裝飾，沒有資訊。
- **成本**：中。SVG 半場圖、符號 CSS、色票。

## 方向 C：手翻記分板（深色優先）
**一句話**：老式手翻記分板的方塊數字，深色底、骨白數字，晚上看比賽的氣氛；不是 LED，不發光。

```
████████████████████████████████████████████████████████████
█  NBA 勝負預測                              時間外 66%      █
█  ┌──┬──┐  ┌──┬──┐                                        █
█  │1 │0 │  │3 │0 │   週五　今晚 12 場                       █
█  └──┴──┘  └──┴──┘                                        █
████████████████████████████████████████████████████████████
 07:00  勇士 ┌──┬──┐ ├─────○▓▓▓───┤ ┌──┬──┐ 湖人
             │3 │4 │                │6 │6 │
             └──┴──┘                └──┴──┘
```
- **識別**：
  - 勝率與日期用「翻牌方塊」呈現：每個數字一個圓角小方塊，方塊中間有一條細縫（翻牌的接縫）。純 CSS。
  - 主視覺是大的日期方塊。
- **色票（深色為主，淺色為輔）**：
  - 板 `#16201B`（深墨綠，非近黑；記分板漆色）、方塊 `#22302A`、骨白數字 `#E9ECE4`、次要 `#9AA79E`、線 `#2E3D36`；
  - 淺色模式反轉成紙 `#EEF1EC` 加深綠方塊。
  - 命中／未中用 `#6CC48F`／`#F08070`。
- **字體**：數字用 **Barlow Condensed 700**（只載數字）；中文系統字。
- **動態**：載入時方塊數字翻一次（每個方塊 120ms 錯開，總長 ≤ 0.6 秒），`prefers-reduced-motion` 時關閉。
- **風險**：
  - 最接近 frontend-design 警告的「深底＋單一亮色」套路；這裡的亮色是骨白而不是酸綠，但整體仍偏戲劇化。
  - 方塊數字在 375px 會比較佔空間，每場可能要三行。
  - 使用者原本嫌「太花」；這個方向的戲劇性最強，最容易被說太花。
- **成本**：中高。方塊元件、深色優先的色票、翻牌動態。

## ui-ux-pro-max 查詢與取捨
| 查詢 | 回傳重點 | 取捨 |
| :- | :- | :- |
| `--domain style "editorial data sports restrained minimal"` | Minimalism & Swiss Style：留白、幾何、高對比、格線、不用陰影漸層；要求對比 4.5、鍵盤、可見焦點、reduced-motion | 採用它的格線與無陰影原則（三個方向都用）；不採用「黑白單色」，因為那就是 v2 的平淡來源 |
| `--domain typography "chinese traditional sans serif headline numbers sports"` | 繁中：Noto Serif TC＋Noto Sans TC；運動：Barlow Condensed＋Barlow | 不採用 Noto 中文網頁字型（數 MB、多請求）；採用 **Barlow Condensed／Semi Condensed，只給數字**，用 `text=` 子集化 |
| `--domain google-fonts "monospace tabular numbers scoreboard digital"` | Share Tech Mono、Lekton、Monofett 等等寬字 | 不採用：等寬數位字型會把頁面帶向「電子看板／科技感」，而且 frontend-design 把「用等寬字當資料標籤」列為套路；Barlow 的 tabular 數字已夠對齊 |
| `--domain color "sports dark mode scoreboard warm"` | Podcast 深色＋橘、Sports Team 紅 | 不採用橘或紅當主色。C 用深墨綠＋骨白，是記分板漆色而不是品牌色 |
| `--domain chart "timeline schedule progress single value"` | Bullet chart：數字與目標並列，門檻區不能只靠顏色 | A 的「共用中線」就是一列一列的 bullet：目標是 50%，數字永遠以文字標出，填色只是加強 |

## 共用的細節質感（三個方向都做）
- **狀態標記**：「尚未開賽」用次要墨；「終場」用墨色加粗；
- **空狀態文案**：「今天沒有比賽。下一場是 10/31 週六。」需要 `next_tip`，已有。
- **頁尾**：資料更新時間、免責、資料來源排成兩欄，手機一欄。
- **深色模式氛圍**：A、B 用帶藍的深灰；C 本身就是深色優先。

## 我的建議
**選 A。** 它延續使用者已經接受的 v2 記憶點，把它從「每列的小元件」升級成「整頁的結構」。設計感來自結構而不是裝飾，也最符合誠實立場：一眼看出今晚哪些場次其實接近五五波。B 的符號識別有趣，但兩個彩色和紅色的語意有風險；C 最有氣氛，但最可能被說「又太花」。

## 實作（選定後）
1. CSS 與字型（數字子集化）；golden 只動 `<style>` 段與 `<head>` 的字型連結（靜態站）。
2. 版面元件（A：中線結構與端點；B：符號與半場圖；C：方塊）。
3. 預覽：`scripts/preview_site.py`，淺色、深色、375px。
